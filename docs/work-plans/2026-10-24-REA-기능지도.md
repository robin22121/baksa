| 결정 | 내용 |

## §3 작업 단위 (병렬 조사 3개)

### A 기능 지도
- 세목별 메인·메뉴 클래스(Main100?/Men100/Main200/Men200…, TaxLauncher)와 resources 목록의 폼을 묶어, 화면 → 기능 목록을 만든다. 폼마다 버튼·라벨 문자열(user_strings)로 기능을 한 줄 설명.
- 산출: `docs/rea/feature_map.md`

### B 양도 계산 흐름
- `Cal100gr_2025`(+ `Cal100`, `Jasan1xx`, `HighInfo*`, `CityInfo_JU2022`)의 호출 간선을 따라 계산 엔진 클래스·메서드를 찾고, 계산 순서(양도차익 → 비과세·고가 안분 → 장특 → 기본공제 → 세율 → 가산세)와 분기 조건을 사람 말로 정리. 세율·공제율 상수가 코드에 있으면 연도별 표로(법령과 대조 후보).
- 산출: `docs/rea/calc_flow_양도.md`, `docs/rea/diff_law.md`

### C DB
- SQL 문자열(SELECT/INSERT/UPDATE/프로시저 이름)을 여러 클래스에서 모아 테이블·컬럼 목록과 화면 대응을 만든다. U2(폼 열기만으로 레코드 생성)·U4(계산 버튼이 저장)를 일으키는 SQL이 있으면 표시.
- 산출: `docs/rea/db_tables.md`

## §4 종료 조건

1. 세 문서가 있고, 각 문서 끝에 Evidence ID·조사한 클래스 목록·미확인 목록이 있다.
2. `feature_map.md`가 5세목 모두를 덮는다(세목별 화면 묶음과 기능 설명).
3. `calc_flow_양도.md`가 C000·C001 경로(일반 과세, 1세대1주택 고가)의 계산 순서를 클래스·메서드 출처와 함께 설명한다. 메인이 C000 결과(8항목 match)와 모순이 없는지 확인한다.
4. 저장소에 디컴파일된 코드 블록이 없다(메인이 `grep`으로 확인: 문서 안 코드 펜스는 식별자 목록·표만).
5. 라이선스·등록 관련 클래스를 분석하지 않았다(조사 목록에 없음).
