> 상태: [설계]

> 기준 문서: `docs/ANALYSIS_PLAN.md`(분석 계획, 단계·금지 사항), `docs/decisions.md`

이 문서는 `ANALYSIS_PLAN.md`의 6단계를 **윈도우 PC에서 실제로 돌릴 수 있는 작업장**(폴더·파일 규격·도구·사람/에이전트 분업·종료 기준)으로 구체화한 것이다. 분석 계획 자체(무엇을·왜)는 바꾸지 않는다.

## §0 이번에 확정할 것

| 결정 | 내용 | 초안과 다른 점·이유 |
|---|---|---|
| 두 PC 역할 | Mac = 설계·문서·검토. Windows = 양도박사 조작·파일 분석·스크립트 실행. 동기화는 `origin/main`(GitHub) 하나로만 | 분석 계획에 없던 항목. 파일을 메일·USB로 옮기면 어느 쪽이 최신인지 잃는다 |
| 척추 케이스 C000 | 단순 케이스 1건을 먼저 **1~4단계 끝까지** 통과시킨 뒤 화면·케이스를 넓힌다 | 계획은 단계 순서(1단계 전체 → 2단계 전체)다. 2단계에서 파일 형식을 알아야 1단계 인벤토리의 "타입" 열이 정확해지므로 **얇게 한 바퀴**가 먼저다 |
| 입력 데이터 | 양도박사에 넣는 납세자는 전부 **가상**(이름·주민번호·주소). 실제 납세자 자료는 쓰지 않는다 | 캡처·DB 덤프·전자신고 파일을 분석 산출물로 다루려면 개인정보가 없어야 한다 |
| 산출물 형식 | 분석 결과는 전부 **표**(md·csv·yaml)로 둔다. 캡처·원본 파일은 근거일 뿐 산출물이 아니다 | 새 프로그램 설계 입력으로 바로 쓰기 위해 |
| 전자신고 파일 파싱 | **바이트 단위** 고정폭, 인코딩 CP949. 문자 단위 슬라이싱 금지 | 한글 2바이트. 문자로 자르면 한글 뒤 필드가 전부 밀린다 |
| 세법 계산기 | `tools/calc/`에 조문 단위로 **처음부터** 짠다. 다른 프로젝트 코드는 참조하지 않는다 | 사용자 지시(2026-10-22, taxflow 참조 금지). `docs/decisions.md`에 기록 |
| DB 분석 중단 기준 | 2단계에서 저장 파일 형식을 **2시간** 안에 못 밝히면 DB 분석을 보류하고 3단계(전자신고 파일·인쇄물)로 데이터 모델을 복원한다 | 독자 포맷·암호화면 블랙박스 원칙상 더 파지 않는다. 전자신고 파일이 실제 출력 규격이므로 손실이 작다 |

## §2 정의

### 2.1 용어

| 용어 | 뜻 |
|---|---|
| 화면(screen) | 양도박사의 입력 화면 하나. `screen_NN`(두 자리 순번)로 부른다. 순번은 신고 1건을 입력하는 자연 순서 |
| 항목(field) | 화면 안의 입력 칸 하나. `screen_NN.field_id`(영문 snake_case, 메인이 정함) |
| 케이스(case) | 입력값 묶음 + 양도박사 산출값 + 법령 기준 계산값. `C###` |
| C000 | 척추 케이스. 1주택자가 아닌 일반 납세자, 주택 1채, 보유 3년 이상 5년 미만, 거주 없음, 기본세율, 감면 없음, 예정신고. 분기(비과세·중과·감면·안분)가 하나도 걸리지 않는 가장 단순한 길 |
| 오라클 | 양도박사 산출값. 정답이 아니라 **비교 대상**. 정답은 법령 |
| 1바퀴 | C000이 §2.3의 산출물 6종을 모두 갖춘 상태 |
