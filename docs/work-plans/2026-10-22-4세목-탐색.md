## §1 확인한 사실

- 메인 버튼의 auto_id는 `bTax100`(양도), `bTax200`(상속), `bTax300`(증여), `bTax301`(주식평가), `bTax500`(종부세)다. 이름은 `상 속 세`, `증 여 세`처럼 공백이 섞여 있다 (`docs/env.md` 환경 점검 출력).
- 양도소득세 세목 창을 WM_CLOSE로 닫으면 "프로그램을 종료하시겠습니까?"(예/아니오) 창이 뜬다. 다른 세목 창도 그럴 가능성이 높다(가정). `allow.yaml` `modals`에는 이 창에 `아니오`를 누르도록 등록돼 있어서, 세목 창은 닫히지 않고 남는다.
- 현재 `explore.py`는 루트를 `allow.yaml`의 `root` 하나로만 받는다. `dry_run`은 루트를 직접 연 경우 `close_screen`만 하고 모달은 처리하지 않는다 (`tools/drive/explore.py` `dry_run`).

## §2 정의

- 세목 창은 실행 시작 전부터 열려 있었다면 닫지 않는다. 이번 실행에서 연 세목 창은 닫기를 시도하되, 종료 확인 모달에는 `아니오`를 누르고 창은 남겨 둔다. 그 사실은 run 요약 `remaining_screens`에 기록한다.
- 그 외의 판정 정의는 탐색기 계획서 §2를 따르고, 완료 판정은 수정된 §4를 따른다.

## §3 작업 단위

### W1 explore.py `--root`
- 변경 파일: `tools/drive/explore.py`
- 모델: implementer(Sonnet)
- 내용:
  - `--root <버튼명>`을 추가한다. 주면 `allow.yaml`의 `root` 대신 그 값을 쓴다.
  - 세목 창의 화면 키는 루트 이름과 같다고 가정한다(제목에서 데모 문구를 지운 값). 실제 제목이 다르면 dry-run 출력에 실제 제목을 보여 준다.
  - `dry_run`이 루트를 직접 연 경우, 닫을 때도 실탐색의 `close_child`와 같은 모달 처리를 거친다.
- 완료 기준: `--root 상속세 --dry-run`이 상속세 창의 버튼을 허용/금지/unreviewed로 분류해 출력한다. 끝난 뒤 처음 보는 모달이 남아 있지 않다.

### W2 세목별 허용 목록과 실탐색 (메인)
- 변경 파일: `tools/drive/allow.yaml`의 `screens`에 세목 화면 4개를 추가한다.
- 세목마다 dry-run을 하고, 메인이 §0 원칙대로 허용 목록을 쓴 뒤 실탐색을 한다.

## §4 종료 조건 (실행 전에 고정)

세목 4개 각각에 대해 다음을 확인한다.
1. dry-run 출력과 메인이 쓴 허용 목록이 계획서 구현 결과에 적혀 있다.
2. 실탐색 종료 코드가 0이고, 오류 0줄이다. 허용 버튼마다 `flow.jsonl` 행이 있다.
3. 데이터 판정은 수정된 탐색기 §4-4를 따른다. `.fdb`는 헤더·TIP 페이지만 바뀌어야 하고, ini 변화는 기록만 한다. `added`/`removed`는 0개여야 한다.
4. 실행이 끝난 뒤 남은 화면은 실행 전 화면 집합에 이번 루트 세목 창을 더한 것 이하다.
5. 메인이 세목마다 루트 화면 캡처 1장과 대표 하위 화면 1장을 직접 열어 json의 제목·버튼과 대조한다. 버튼을 눌러도 화면이 바뀌지 않으면 U로 기록한다.

처음 보는 모달 때문에 중단(종료 코드 2)되면, 메인이 그 모달을 보고 `modals`에 추가한 뒤 다시 실행한다. 다시 실행한 횟수는 구현 결과에 적는다.

## §5 열린 질문

- 세목 창이 양도소득세처럼 "대상자 등록 전에는 하위 화면이 막혀 있는" 구조인지. 기본값: 막혀 있으면 U로 기록하고, 해당 세목의 케이스 작업 때 가상 대상자를 등록한 뒤 다시 탐색한다.

## §6 범위 밖

- 가상 대상자 등록(쓰기)과 그 뒤의 하위 화면: 케이스 작업(C000 등)에서 한다.
- 인벤토리 문서화(W2 `flow.md`·`screen_NN.md`): 별도 작업.
