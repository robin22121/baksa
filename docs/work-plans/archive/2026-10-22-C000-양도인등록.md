Fable 검토 중 받아들인 것: 입력 리허설, 칸마다 Tab으로 확정한 뒤 다시 읽기, 주민번호는 숫자만 입력, 콤보에 Enter 금지(Tab 또는 목록 선택), 글자 입력 직전 전경 창 확인, 한글은 set_value가 안 되면 클립보드 붙여넣기, 주소검색·세무서코드 자동 채움을 예상 부수효과로 기록, 그리드는 재조회 후 확인, 연도 필터 "전체", 백업 헤더 확인과 복원 뒤 지문 대조, §4 문구 구체화, 재실행·복원 상한.
받아들이지 않은 것: 백업을 양도박사 종료 상태에서 뜨기. Firebird가 내장형(`fbembed.dll`, 별도 서버 프로세스 없음)이고 백업 시점에는 쓰기 트랜잭션이 없다. 대신 백업본의 헤더(페이지 크기·페이지 수)가 원본과 같은지 확인한다. 복원은 종료 상태에서만 한다.

## §1 확인한 사실

- 양도인 등록 화면(탐색 seq 23, `docs/inventory/raw/023_양도소득세_inplace.json`)의 입력 컨트롤은 uia `auto_id`로 식별된다.
  - 글자 칸: `emNAME`(양도인 성명), `emJUMIN`(주민등록번호), `emTEL`, `emHP`, `emJUSO`(주소), `emPOST`, `emEMAIL`, `emSEOCD`(세무서코드), `emSEOONLINE`(계좌번호), `emGUNAME`(지방세관할), `emMEMO`
  - 콤보: `emSEONAME`(관할세무서), `cbMen100Year`(양도연도 필터)
  - 라디오 그룹: `emJASANGU`(양도구분: 부동산·국외자산·주식(국내)·토지등 매매차익·파생상품), `emSINGOGU`(신고구분: 예정·확정·수정·기한후), `emBORN`(내국인·외국인), `emOUTJUSO`(거주자·비거주자)
  - 국적·거주지국 `emNATIONALITY`·`emCOUNTRY`는 기본값이 "한국"이다.
  - 그리드: `cxGrid1`(양도인 리스트), `cxGrid2`
  - 버튼: `등록`, `수정`, `삭제`, `수정신고`, `저장`, `취소`, `편집제한`/`편집허용`, `다음단계`. 캡처 023에서 처음에는 `수정`·`삭제`·`저장`·`취소`가 비활성이다.
- 화면 문구: "등록된 양도인을 선택하고 「다음단계」를 누르면 자산등록 화면으로 이동합니다" (캡처 023).
- 탐색에서 `2.`~`4.`를 눌러도 화면이 바뀌지 않았다(U1).
- Firebird 페이지 비교 도구가 있다(`.scratch/fdbpages.py`). 읽기만 하면 헤더(0)와 TIP 페이지만 바뀐다(탐색 2차·4세목).
- 지금 양도박사에는 메인과 5세목 창이 열려 있다. 양도소득세 창은 FAQ 화면이 아니라 마지막으로 연 화면 상태일 수 있다.
- Firebird는 내장형이다. 설치 폴더에 `fbembed.dll`, `fbclient.dll`, `gds32.dll`, `FirebirdSql.Data.FirebirdClient.dll`이 있고, 별도 Firebird 서버 프로세스는 없다(2026-10-22 tasklist).
- 가정: 저장할 때 "저장하시겠습니까?" 같은 확인 모달이 뜬다. 필수값이 비어 있으면 경고 모달이 뜬다. 관할세무서는 주소로 자동 선택될 수도, 직접 골라야 할 수도 있다.

## §2 정의

- **단계 파일** `cases/basic/C000.steps.yaml`: 순서대로 실행할 동작 목록.
  ```yaml
  window: 양도소득세            # 대상 세목 창(제목, 데모 문구 제외)
  steps:
    - press: 1.양도인등록
    - press: 등록
      expect_enabled: [저장, 취소]     # 누른 뒤 활성이어야 할 버튼
    - radio: {group: emJASANGU, value: 부동산}
    - radio: {group: emSINGOGU, value: 예정}
    - radio: {group: emBORN, value: 내국인}
    - radio: {group: emOUTJUSO, value: 거주자}
    - text: {id: emNAME, value: 가상양도인}
    - text: {id: emJUMIN, value: "{rrn}"}       # fake_rrn.py 결과로 치환
    - text: {id: emJUSO, value: 서울특별시 마포구 가상로 1}
    - combo: {id: emSEONAME, value: 마포}       # 실패하면 중단하고 메인이 판단
    - capture: before_save
    - press: 저장
      modals: {"확인|저장하시겠습니까?": 예}       # 실제 문구는 첫 실행에서 확정
    - capture: after_save
    - verify_grid: {id: cxGrid1, contains: 가상양도인}
  ```
- **입력 규칙**:
  - 글자 칸에 쓰기 전에 대상 창을 `set_focus()`하고, 전경 HWND가 대상 창인지 확인한다. 아니면 `fail`. 확인 결과는 실행 기록에 남긴다.
  - 값은 ValuePattern `set_value`로 넣는다. 그다음 Tab으로 포커스를 내보내 확정하고 다시 읽는다. 다시 읽은 값이 다르면 `type_keys`, 한글은 클립보드 붙여넣기(Ctrl+V)로 한 번 더 시도한다.
  - 주민번호는 숫자 13자리만 넣는다(하이픈 없음).
  - 콤보는 Enter를 쓰지 않는다. 값을 넣고 Tab으로 확정하거나 목록에서 고른다. 콤보 단계 뒤에는 창 제목과 `저장` 버튼 상태가 그대로인지 확인한다.
  - 주소 칸을 클릭했을 때 우편번호 검색 창이 뜨거나 세무서코드(`emSEOCD`)가 자동으로 채워지는 것은 예상 부수효과다. 단계 파일 `modals`/`side_effects`에 적고, 저장 전에 `emSEOCD` 값을 읽어 기록한다.
  - 시작할 때 연도 필터 `cbMen100Year`가 "전체"인지 확인한다.
- **동작 하나의 결과**: `ok`, `fail`(칸을 못 찾음, 값이 안 들어감, 기대 버튼이 비활성), `abort`(처음 보는 모달). `fail`이나 `abort`가 나오면 즉시 멈춘다. 입력한 값은 다시 읽어서(`get_value`/`window_text`) 원하는 값과 같은지 확인한다.
- **실행 기록**: `cases/basic/C000.run_<시각>.json`에 단계별 결과, 다시 읽은 값, 모달, 캡처 경로, fdb 페이지 비교 결과를 남긴다. 캡처는 `docs/screens/C000_NN_<이름>.png`(gitignore).
- **하위 화면 탐색**: 저장이 확인되면 그리드에서 `가상양도인` 행을 고른다(행 셀에 PostMessage 클릭). 그다음 탐색기를 `--root 양도소득세`로 실행하는데, 허용 목록은 `2.자산등록`, `3.양수인등록`, `4.세액계산`만 둔다(`allow.yaml`에 `양도소득세_C000` 프로필로 분리하거나 실행 인자로 지정). 하위 화면 안의 버튼은 누르지 않는다(기록만).

- 완료 기준: §4 1~2.

## §4 종료 조건 (실행 전에 고정)

1. `python tools/fake_rrn.py`가 검증숫자를 다시 계산해 일치를 출력하고, 공개 검증 예시 번호 1개로 공식이 재현된다.
2. `case_input.py --dry-run`은 `등록`을 누르지 않은 상태에서 글자 칸·라디오·콤보·버튼을 찾는다. 못 찾은 것이 0개다. 비활성 버튼은 "찾음(비활성)"으로 세고, `modals:`의 버튼은 대상에서 뺀다.
3. 리허설(`C000.rehearsal.steps.yaml`, `취소`로 끝남)의 종료 코드가 0이고, 모든 단계가 `ok`다. fdb 페이지 비교는 헤더·TIP만 바뀌어야 한다.
4. 실제 실행의 종료 코드가 0이고, 모든 단계가 `ok`다. 다시 읽은 값의 비교 규칙은 다음과 같다.
   - 글자 칸: 공백을 지운 값이 같다.
   - 주민번호: 숫자만 뽑은 13자리가 같다.
   - 라디오: 해당 항목의 `is_selected()`가 True다.
   - 콤보: 선택된 문자열에 단계 값이 들어 있다.
   - 매 글자 입력 직전 전경 HWND가 대상 창이었다는 기록이 있다.
5. 저장 뒤 `저장`·`취소` 버튼이 다시 비활성이다. `1.양도인등록`을 다시 눌러 재조회한 `cxGrid1`에 `가상양도인` 행이 정확히 1개 있고, 행 수가 저장 전보다 1 많다. 메인이 `after_save` 캡처를 직접 연다.
6. 페이지 비교 결과를 파일별·페이지 타입별 변경 수 표로 남긴다. `neoTax.fdb`에서 pointer·data·index root·index 페이지(타입 4/5/6/7) 중 1개 이상이 바뀌었다. 다른 `.fdb`는 헤더·TIP만 바뀌었다. `added`/`removed`는 0개다. 데이터 변화가 `neoTax.fdb`가 아닌 파일에서 나오면 실패가 아니라 §1 사실 정정으로 기록한다.
7. 하위 화면 탐색에서 `2.자산등록`, `3.양수인등록`, `4.세액계산` 각각의 화면 키(탐색기 §2 정의)가 양도인 등록 화면과 다르다(U1 해소). 메인이 캡처 3장을 열어 패널 제목을 확인한다. 이 탐색에서 데이터 페이지가 바뀌면 실패가 아니라 U 결함으로 기록하고 메인이 판정한다.
8. 끝났을 때 열린 모달이 0개다. 복원을 했다면 복원 뒤 fdb 지문이 백업과 같다.
9. 같은 단계 파일의 재실행은 최대 3회, 복원은 최대 1회다. 넘으면 멈추고 보고한다. 횟수는 구현 결과에 적는다.
