## §1 확인한 사실

- 양도박사가 관리자 권한(elevated=True)일 때는 일반 권한 Python에서 `OpenProcess(VM_READ)`가 실패했다. pywinauto win32의 `automation_id`는 AccessDenied, `PrintWindow`는 0을 반환했다. RunAsInvoker로 다시 띄운 뒤에는 elevated=False이고 VM_READ가 허용됐다 (`.scratch/elevprobe.py`, 2026-10-22).
- 메인 창은 제목 "양도박사2026", 클래스 `WindowsForms10.Window.8.app.0.2dac507_r7_ad1`이다. uia에서 Button 26개를 이름과 좌표로 읽었다. 세목 버튼은 `양도소득세`, `상 속 세`, `증 여 세`, `주식평가`, `종합부동산세`이고 이름에 공백이 섞여 있다. MenuBar는 없다. 같은 프로세스에 제목 없는 보이는 창이 하나 더 있다 (`.scratch/ctl_uia.txt`).
- `양도소득세` 버튼을 `invoke()`하면 새 최상위 창이 열린다. 제목은 "양도소득세 ▶ 본 프로그램은 데모버전이며…"이다. 안에 있는 버튼은 다음과 같다.
  - 작업 순서: `1. 양도인 등록`, `2. 자 산 등 록`, `3. 양수인 등록`, `4. 세 액 계 산`
  - 보조: `양도·취득가액 안분계산`, `도움말·법령 보기`, `공서식 인쇄·작성`, `기준시가 조회`, `환경 설정`, `자료 백업`, `자료 복원`, `원격지원`
  - FAQ 탭(`화면인쇄`, 페이지 `1`·`2`, FAQ 링크 버튼)
  - DevExpress WinForms다(`panelControl*`, `groupControl*`) (`.scratch/yd_0.txt`).
- 화면 복사 캡처는 창이 맨 앞에 있어야 맞다. 가려진 상태로 찍으면 위에 있는 창이 찍힌다 (`.scratch/yd_0.png`). 배율은 약 175%다.
- **저장 형식은 Firebird**다. `C:\Neoic\Tax2019\Data` 안에는 `neoTax.fdb`(6.7MB, 오늘 09:46 수정 → 납세자·신고 데이터로 추정), `neoPost.fdb`(14MB), `neoapt.fdb`(1.2GB, 2018), `MoctApt.fdb`(1.5GB, 2018)가 있다. 뒤의 셋은 주소와 공동주택가격 참조 DB로 추정한다. 설치 루트에 `firebird.log`가 있다.
- **양도박사는 실행하는 것만으로 파일을 쓴다.** 오늘 09:47 다시 실행했을 때 `backup.ini`, `BACKUP\neoTax20261022.zi`, `neoic_backup\neoTax20261022.zi`(새 폴더), `Font_OK`, `firebird.log`가 생기거나 갱신됐다. 그래서 탐색 지문은 반드시 **탐색 시작 직전**에 뜬다.
- HKCU\Software 아래에 Neoic 관련 키가 없다.
- `C:` 여유 공간은 172GB다.
- `check_env.py`의 버그: `Desktop.windows()`가 돌려주는 래퍼에는 `print_control_identifiers`가 없다. `title_re`가 다른 창을 잡을 수 있다.
- 가정: Firebird는 읽기 트랜잭션만 열어도 헤더 페이지(트랜잭션 카운터)를 갱신할 수 있다. 그래서 `.fdb`의 sha1이 바뀌는 것만으로는 데이터 변경을 판정할 수 없다.
- 가정: 하위 화면의 DevExpress 그리드는 uia에서 셀이 안 보일 수 있다.

## §2 정의

- **화면**: 양도박사 프로세스의 보이는 최상위 창 중 제목이 있고 owner가 없으며 클래스가 `#32770`이 아닌 것. owner가 있거나 `#32770`이면 **모달**이다.
- **화면 키**: 제목에서 데모 문구(`▶ 본 프로그램은 데모버전` 이후)를 지운 전체 제목 + 창 클래스 + 버튼 이름 집합의 sha1 앞 8자리.
- **이름 비교**: 버튼 이름은 공백을 모두 지우고 비교한다.
- **허용 목록 `tools/drive/allow.yaml`**:
  ```yaml
  root: 양도소득세            # 메인에서 누를 시작 버튼
  screens:                   # 화면 제목(데모 문구 지운 것) → 누를 버튼
    양도소득세: [1.양도인등록, 2.자산등록, 3.양수인등록, 4.세액계산, 양도·취득가액안분계산, 도움말·법령보기, 기준시가조회]
  modals: {}                 # 모달 제목 → 누를 버튼 (처음엔 비어 있음)
  ```
  첫 실행의 허용 목록은 위와 같다. `환경 설정`, `자료 백업`, `자료 복원`, `원격지원`, `공서식 인쇄·작성`, `화면인쇄`는 넣지 않는다. 하위 화면은 처음엔 목록이 비어 있으므로 열고 기록만 한다(깊이 1).
- **누르기**: `invoke()`를 별도 스레드에서 실행하고 5초 타임아웃을 둔다. 타임아웃이 나도 실패로 보지 않고 창 변화를 관찰한다. `click_input()` 대체는 쓰지 않는다.
- **간선 판정**: 누른 뒤 최대 5초 안에 다음 셋 중 하나로 판정한다.
  - 새 화면이 생겼다 → `window`
  - 새 모달이 생겼다 → `modal`. 허용 목록 `modals`에 있으면 그 버튼을 누르고, 없으면 캡처한 뒤 **중단**한다.
  - 아무것도 안 생겼다 → `inplace`. 캡처만 한다.
  - 데스크톱 전체에서 **양도박사가 아닌 프로세스의 새 창**(브라우저, PDF 등)이 생기면 `external`로 기록하고, 그 창의 제목과 프로세스 이름만 남긴다. 그 창은 닫지 않고 사람에게 보고한다.
- **복귀**: 자식 화면은 `close()`(WM_CLOSE)로 닫는다. 닫을 때 모달이 뜨면 간선 판정의 모달 규칙을 똑같이 적용한다. 처음 보는 모달이면 중단한다. 복귀한 뒤에는 부모 창이 보이는지 확인한다.
- **캡처**: `set_focus()`를 부른 뒤 `GetForegroundWindow()==hwnd`인지 확인하고 PIL `ImageGrab`으로 창 영역을 찍는다. 포그라운드가 아니면 `PrintWindow(PW_RENDERFULLCONTENT=2)`를 한 번 시도한다. 그것도 검은 화면이면 json에 `capture: "failed"`로 기록한다. DPI 인식(`SetProcessDpiAwareness(2)`)은 pywinauto를 import하기 **전에** 켠다.
- **전역 상한**: 화면 60개, 누르기 300회, 총 30분. 하나라도 넘으면 중단한다.
- **지문**: 설치 폴더 전체 파일의 (상대경로, 크기, mtime, sha1) 목록. 비교 결과는 세 가지로 분류한다.
  - `added`/`removed`: 생기거나 사라진 파일
  - `content`: 크기 또는 sha1이 바뀐 파일
  - `mtime_only`: mtime만 바뀐 파일
- **산출물** (seq는 3자리):
  - `docs/screens/NNN_<슬러그>.png` (gitignore 대상)
  - `docs/inventory/raw/NNN_<슬러그>.json`: `{seq, path, title, key, rect, edge, capture, controls:[{type,name,auto_id,rect,enabled}], unreviewed:[…], blocked:[…]}`
  - `docs/inventory/raw/flow.jsonl`: 한 줄에 화면·모달·external 하나. `{seq, path, title, key, parent_seq, edge, counts, error?}`
  - `docs/inventory/raw/run_<시각>.json`: 실행 요약(화면 수, 누르기 수, unreviewed 수, 오류 수, 중단 사유, 지문 비교 결과, 소요 시간)

## §4 종료 조건 (실행 전에 고정, 실행 중 바꾸지 않는다)

1. `python tools/check_env.py`가 traceback 없이 끝나고, `[uia] 컨트롤 요약`에 Button이 26 이상이다. 그 출력이 `docs/env.md` "환경 점검 출력"에 붙어 있다.
2. `python tools/drive/explore.py --dry-run`의 양도소득세 화면 **허용** 분류가 `{1.양도인등록, 2.자산등록, 3.양수인등록, 4.세액계산, 양도·취득가액안분계산, 도움말·법령보기, 기준시가조회}`와 정확히 같다. `환경설정`, `자료백업`, `자료복원`, `원격지원`, `공서식인쇄·작성`, `화면인쇄`는 허용에 없다.
3. 실탐색 1회의 조건:
   - 시작 뒤 사람 입력 0회, 종료 코드 0
   - `flow.jsonl`의 error 0줄
   - 허용 버튼 7개 각각에 대해 `flow.jsonl` 행이 있고, edge가 window나 inplace면 png·json이 1쌍씩 있다
   - 처음 보는 모달 때문에 중단되면(종료 코드 2) **이 조건은 실패**다. 메인이 `modals`를 채운 뒤 다시 실행하며, 다시 실행한 횟수를 구현 결과에 적는다
4. 지문 비교: `added`/`removed`/`content`에 **`Data\neoTax.fdb` 말고는 아무것도 없다**. `neoTax.fdb`에 content 변경이 있으면 `docs/decisions.md` 알려진 결함에 Q로 적고 W4 DB 수준 검증으로 넘긴다(이번 작업의 실패는 아님). `mtime_only`는 기록만 한다. ini 파일, `BACKUP`, `neoic_backup`에 변화가 있으면 실패다.
5. 실행이 끝난 뒤 `screens()`가 메인 hwnd 하나만 돌려준다. 양도박사가 아닌 새 창(`external`)은 0개이거나, 있으면 전부 run 요약에 기록돼 있다.
6. 메인이 양도소득세, `1. 양도인 등록`, `4. 세액 계산` 화면의 캡처 3장을 직접 연다. 캡처의 창 제목이 json `title`과 같고, json의 Button 이름이 캡처에 전부 보이는지 확인한다. 결과는 구현 결과 표에 화면별 O/X로 적는다.
7. 총 소요 시간은 30분 이내다. 실패하거나 중단돼서 `neoTax.fdb`를 복원해야 하면, 양도박사를 종료한 상태에서 백업으로 복원하고 복원 여부를 구현 결과에 적는다.
